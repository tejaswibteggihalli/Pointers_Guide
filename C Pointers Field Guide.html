Pointer*s

You wired RAM from gates and wrote @x; M=D in Hack. A C pointer is that same idea with types on top. Step through memory, play with the arithmetic, then drill 70 questions on every edge case that bites.

blue = an address amber = data stored red = undefined behavior

Memory is numbered boxes

Every byte has an address, like RAM[k] in Hack. A variable is a run of boxes with a name.

A pointer is a box holding an address

It is an ordinary variable whose value is another box's number. &x makes the number, *p follows it.

The type decides the step and the width

p + 1 moves one element; *p reads that element's size. Hack had one size: one 16-bit word.

From Hack to C
Everything you learned still holds. This table shows where each Hack idea lands in C and what C adds.

  

    
In nand2tetrisIn CWhat changes

    
      
RAM[k], a 16-bit wordThe byte at address kC addresses bytes. An int spans 4 of them, so objects have a size and alignment.

      
@x then D=A&xSame thing: the address of x, not its contents.

      
@p, A=M, then M*pLoad the pointer into A, then M is the pointee. C emits the width the type needs (1, 2, 4, 8 bytes).

      
A=A+1p + 1Hack always steps one cell. C steps sizeof(*p) bytes.

      
SP, LCL, ARG, THIS, THAT are RAM[0..4]Stack pointer, frame pointer and friends are registers the compiler managesThey are pointers too. push local 2 is *(LCL + 2).

      
pointer 1 and that ip = addr; p[i]Exactly the VM's way of implementing a[i]: set THAT, then index off it.

      
Jack a[i]a[i] is *(a + i)Same definition. C also scales by element size.

      
SCREEN = 16384, KBD = 24576volatile uint16_t * at a fixed addressMemory-mapped I/O works the same way on bare metal. In an OS process those addresses are not yours.

      
Memory.alloc / deAllocmalloc / freeSame contract and the same bugs: leaks, double free, use after free.

      
A Jack object variableA pointer to a heap structIn Jack the pointer is hidden. In C you see and manage it.

      
Any address in 0..32767 worksOnly mapped addresses workThe MMU and OS add protection (segfaults). Most bugs do not trip it; they just corrupt data.

      
Code lives in ROMCode lives in memory tooFunction pointers are addresses of code. Returning into a smashed stack runs attacker code.

      
The CPU does what you wroteThe compiler may assume UB never happensAn optimizer rewrites your program under that assumption. Hack had no optimizer between you and the chip.

Precedence, tightest first

      
// 1  postfix  a[i]  f()  s.m  p->m  p++  p--
// 2  prefix   *p  &x  !x  -x  ++p  --p  sizeof  (T)
// 3  binary   * / %   then   + -   then   < <= > >=
//    then     == !=   &&   ||   ?:   =   ,

*p++   // *(p++)
*p.x   // *(p.x)  not (*p).x
&a[i]  // &(a[i])
->     // binds tighter than * and &
